# 可配置营销输出与日语读音分离设计

## 目标

让每个方案在“批量与上传”中独立定义营销输出的数量：标题数量、概要数量、标签最少/最多数量。默认及现有方案统一设为标题 3 条、概要 1 条、标签 5–10 个；标题与概要都不得少于 1 条。

日语正文中的内联读音标记（例如 `漢字（かな）`）仅供 TTS 使用。营销标题、概要、标签、封面提示词、营销缓存和本地兜底均使用去读音后的展示文本 `漢字`，因此读音与括号不显示，也不会影响任何营销文本的字符数。

不再由运行时代码硬编码或重写营销标题的字符范围。各方案的可编辑营销提示词是标题与概要长度、文案风格和语言的唯一来源；程序只验证结构数量与非空内容。

## API 路由

“API 账户与用途分配”中的“文本账户”是所有写作任务的显式选择，包括洗稿、标题/概要、分镜提示词、人设分析和封面提示词。选择账户 1–6 时，文本请求必须使用该账户的 Base URL、Key 和文本模型；未选择账户时，才继承默认统一/旧文本配置。图片账户不参与上述文本请求。

已有实现已经遵从此优先级。此次将以回归测试锁定它，避免后续改动使账户选择失效。

## 设计

### 配置与迁移

新增四个配置字段：`marketing_title_count`、`marketing_synopsis_count`、`marketing_tag_min_count` 与 `marketing_tag_max_count`。配置加载时将缺失值迁移为 3、1、5、10；将不合法值钳制为标题/概要至少 1，标签最小值至少 0 且最大值不小于最小值。现有方案、默认设置和方案模板都写入这组新默认值，并同步其营销提示词及 JSON 示例为相同数量。

原 `marketing_title_min_chars` 与 `marketing_title_max_chars` 不再参与营销生成、校验或请求提示；保留旧字段只为读取旧方案时兼容，GUI 不再呈现为营销约束。

### GUI

“批量与上传”替换旧的候选标题最少/最多字输入为：标题数量、概要数量、标签最少数量、标签最多数量。保存当前方案时，对这四项进行本地校验，并显示明确错误；其余营销提示词仍可完整编辑。重建标题/概要的确认文案从固定“3 个标题、2 个概梗”改为当前方案的动态数量。

### 生成、解析与缓存

营销阶段从配置读取数量，按该数量构造输出 JSON 合约与重试说明；提示词内容不再被正则替换字数规则。JSON 解析保留对应数量的标题、概要与标签，校验恰好满足配置的标题/概要数量以及标签闭区间。缓存哈希包含四项数量，因此更改方案数量会自动令旧营销缓存失效。

本地兜底基于同一展示文本生成配置数量的标题与概要，并只保留配置允许的标签数量。候选 TXT、`marketing_candidates.json`、`metadata.json`、上传标题随机选择和封面输入均消费同一动态集合。封面策划可遍历全部候选，不会假设固定的第二条概要。

### 日语展示文本

在 `text_annotations` 中提供复用的展示文本函数，识别当前已支持的合法日语内联注音形式，并只删除读音括号，保留原书写词。营销材料、模型候选解析后的标题与概要、兜底标题与概要、`metadata`、候选 TXT 和封面格式化上下文都通过该函数；中文和没有内联读音的文本保持不变。TTS 与字幕现有函数和调用链不改动。

### 回归测试

覆盖：

- 日语注音在营销输入、模型候选、兜底和封面上下文中都变为无括号的汉字，同时 TTS 行为不变。
- 自定义数量（例如 2 标题、3 概要、4–6 标签）驱动 JSON 校验、缓存失效、TXT 输出和兜底集合；标题/概要的零或负数配置被安全限制为 1。
- 提示词里指定的标题字数不会被代码重写，且程序不再以旧 40–70 范围拒绝候选。
- 文本账户已选时覆盖统一默认文本 API；未选时继续回退默认路由。
- 现有方案及模板迁移到 3 / 1 / 5–10，不触碰任务的已保存设置快照或生成媒体。

## 非目标与兼容性

不修改 TTS 读音、字幕显示、图片生成账户、已完成任务的媒体文件或历史任务快照。旧缓存因为新的输入哈希及数量合约会在用户手动重建营销信息或后续重新运行时更新；不会静默改写已有的已上传标题。

# 任务内专名本地化与同语种润色设计

## 背景

现有“AI 洗稿改写”只将段落按批交给模型输出正文。它没有结构化的专名映射、跨批记忆、输出完整性检查或残留检测。用户希望它与“小说本地化工作台”一致：在不翻译语言的前提下，按可编辑 Skill 改写表达，并可选地把人物及相关专名改为同一语言文化中的新名称，且全任务稳定一致。

## 目标

- 中文原文输出中文润色稿；日语原文输出日语润色稿；本功能不提供翻译。
- 通过现有可编辑 `ai_rewrite_prompt`（界面改名为“洗稿 Skill”）约束重写风格与不可改变的内容。
- 默认关闭的“专名本地化/改名”开关可选地改写人名、地名、家族名、组织名、机构名和种族名。
- 映射范围仅限一个流水线任务；同一任务的所有洗稿批次、重试与重做可追溯且一致，不同小说绝不共享。
- 任何失败或校验不通过都不让部分洗稿结果或临时映射进入 TTS、分镜或最终正文。

## 非目标

- 不新增原文语言到目标语言的翻译工作流。
- 不将名称映射保存为全局方案或跨小说记忆。
- 不做需要人工交互的逐名确认界面；任务报告保留映射与警告，供用户检查。

## 配置与界面

保留现有 `ai_rewrite_enabled`、`ai_rewrite_batch_chars` 和 `ai_rewrite_prompt`。

新增配置：

- `ai_rewrite_proper_noun_localization_enabled`：默认 `false`。启用后模型可生成受限类别的专名映射，并由本地代码统一应用。
- `ai_rewrite_min_length_ratio`：默认保守下限，用于避免模型把整批或全文摘要化。
- `ai_rewrite_max_length_ratio`：默认保守上限，用于避免异常扩写。

GUI 的“洗稿提示词”显示为“洗稿 Skill（可编辑）”，补充说明：Skill 只决定表达和风格；开启专名本地化后，名字风格自动跟随检测出的原文语言。GUI 还提供“专名本地化/改名（任务内记忆）”复选框及类别说明。

旧配置缺少的新字段时自动采用安全默认值，不改变既有任务行为。

## 语言判定

洗稿前从完整正文进行轻量、可解释的语言判定：具有足够假名比例的正文判定为日语，否则默认中文。判定结果只用于提示模型和质量检查，不改变原文内容。日语输出必须含合理的日语文字特征；中文输出不得被意外整体改写为日语。无法可靠判定时只记录警告，不阻断短标题或极短正文。

## 每批 API 契约

启用专名本地化时，文本模型必须只返回 JSON：

```json
{
  "rewritten_text": "本批润色后的同语种正文",
  "new_replacements": [
    {"category": "人名", "source": "原名", "target": "新名", "notes": "简短依据"}
  ],
  "warnings": []
}
```

系统提示词固定要求：保留剧情、人物关系、因果、视角、结局和信息量；严格以检测出的原文语言输出；不得新增事件、人物、设定或心理；已有映射为最高优先级；新名称必须符合原文语言文化且明显不同于原名。用户的 Skill 作为高优先级风格规则附加在固定安全规则之后。

每批用户消息包含当前正文、已确认映射和批次标识。后续批次只使用此前成功批次产生的映射。不开启专名本地化时维持纯正文输出的旧 API 契约，以保证旧中转接口兼容。

## 映射校验和应用

新增独立的 `app/rewrite_localization.py`，定义下列无副作用函数和数据格式：

- 解析、规范化和验证结构化模型结果；
- 判定原文语言和输出语言特征；
- 校验映射类别、长度、原词存在性、同源词唯一目标、目标名称与原名的明显差异；
- 以原词长度降序应用映射；
- 检测最终正文中仍残留的强制改名原词。

允许类别为：人名、地名、家族名、组织名、机构名、种族名。程序拒绝空值、未知类别、原文未出现的原词、过长值及同一原词映射到冲突目标的候选。人物等单字或容易成为普通词的短原词不由本地盲目替换；它们保留为模型上下文中的规则并在报告中提示人工检查，避免把普通正文误改为名字。

最终成稿对安全映射进行本地统一替换，再做残留检查。存在残留时记录警告和报告条目；不覆盖已生成的其他任务输出。

## 失败、检查点与产物

洗稿在任务目录内维护运行期检查点。每个成功批次后持久化其正文、临时映射、警告和源文本哈希；检查点仅用于同一任务的安全续跑，不会进入全局配置。

每批遵循以下故障策略：

1. 非空、JSON、语言和长度检查首次失败时，用严格格式说明重试一次。
2. 重试仍失败、接口异常或输出截断时，整次洗稿回退原文；不写入最终改写正文和最终映射。
3. 成功完成所有批次后才原子写入最终正文、映射和报告，并删除运行期检查点。

新增任务产物：

- `text_rewrite_replacements.json`：语言判定、映射、首次出现批次、警告和残留项；
- 扩展的 `text_rewrite_report.json`：前后字数、比例、批次校验、语言和映射数量；
- `text_rewrite_checkpoint.json`：仅未完成时存在的续跑状态。

重做“洗稿和配音”及全量清理会删除上述三项产物，避免复用旧规则或名字表。

## 管线集成

`stage_clean` 的阶段顺序保持不变：去外围文本、洗稿、TTS 净化、自动读音、切片。洗稿成功返回最终本地替换后的文本，后续 TTS、字幕、分镜和营销模块自动使用同一个改名润色版本。

`_rewrite_story_text` 负责协调任务级状态与原子写入；批处理、提示词构造、结果解析和校验委托给新模块。这样不改变其他 LLM 用途（标题、分镜、封面）的协议。

## 测试与验证

新增不访问外网的单元测试，覆盖：

- 中文、日语语言判定和对应提示词；
- 前一批创建映射、后一批继承同一映射；
- 最终替换的最长优先顺序与残留报告；
- 非法类别、缺失原词、冲突映射、近似名字和单字风险；
- 空输出、坏 JSON、截断、质量比例失败、一次重试和整次回退；
- 功能关闭时维持旧纯文本洗稿行为；
- GUI/config 新字段保存和旧配置迁移；
- 重做洗稿时删除新产物。

完成后运行项目 AGENTS.md 指定的编译验证包，以及相关单元测试。

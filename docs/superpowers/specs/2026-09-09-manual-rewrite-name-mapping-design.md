# 洗稿专名改名失败后的无人值守兜底映射

## 目标

当启用了“专名本地化/改名”且模型多次未能提交有效映射时，流水线仍能无人值守地生成稳定、明显不同的本地兜底名称；人工编辑只作为任务完成后的纠正能力，而不是运行中的必经步骤。

## 流程

1. 结构化洗稿中，模型首次返回近似名称、格式错误映射或缺少要求的映射时，程序携带具体失败原因重试一次。
2. 重试仍失败、但已能从无效映射中确定原词时，本地确定性命名器为该原词生成明显不同的新名称，并通过同一套映射校验。
3. 兜底名称由原词和类别的稳定散列选择，不依赖运行顺序；同一长篇内的同一原词永远得到同一个名称。名称池避免与原词近似、避免同批冲突。
4. 没有任何可识别原词时，本批不能以“零映射成功”结束；程序自动进行额外的仅专名识别/命名请求。该请求仍失败才保留原文并把任务标为失败，而非继续生成不一致的分集。
5. 已确认或兜底映射由本地代码一次性应用于完整改写文本，写入现有 `text_rewrite_replacements.json`，确保后续 TTS、字幕、分镜使用相同名称。长篇项目开启“项目级专名记忆”时，还必须写入项目专名总表，后续分集在洗稿前自动沿用。

## 约束和错误处理

- 本地兜底命名不使用随机数，不会因重跑或任务顺序而改变同一原词的名称。
- 人工事后编辑沿用现有安全校验：原词必须存在、目标不能为空、目标必须与原词明显不同；同一原词不能映射到多个目标。
- 对于长篇项目，模型确认或本地兜底的映射必须合并进项目专名总表；下一个任务不得再次要求为同一原词命名。
- 无 GUI、后台队列和正常 GUI 都不等待人工输入。
- 人工可在任务完成后编辑专名总表；编辑会作为显式的后续重做操作处理，不会在运行中阻塞队列。

## 测试

- 近似名（例如 `林一`）会产生明确的重试指令。
- 重试失败且已知原词时，本地生成稳定、非近似的兜底名称，并只替换原词。
- 同一原词在重新运行和后续分集得到同一个兜底名称；不同原词不冲突。
- 无可识别原词时不能零映射成功，必须触发仅专名识别/命名请求。
- 空值、近似新名、冲突映射会被拒绝；所有自动映射写入报告与项目专名总表。

# 预备分包移除视频并支持重新导入

## 目标

预备分模式将任务整理为不包含任何 MP4 的留档包；以后从“导入文件 / 文件夹”选择该包时，程序能识别它，使用保留的原文和正片音频创建新任务，并在重新执行时调用图片 API 生图、合成新的正片视频。

## 保留与删除规则

- 保留 `_source_input` 中的原文、任务根目录的 `audio_full.mp3`、`cover`、`images` 及整个 `shorts` 目录中的非 MP4 内容。
- `shorts` 中的音频、文字、JSON、字幕及其他非 MP4 文件均保留。
- 递归排除任何扩展名为 `.mp4` 的文件，无论其在任务根目录、`shorts` 或其子目录中。
- 包内已有的图片、封面和 Short 素材只作留档；重新导入时不复制到新任务。

## 可重新导入格式

预备分模式在包根目录写入一份受版本标识保护的 JSON 标记，记录：原文在 `_source_input` 内的相对位置、正片音频 `audio_full.mp3` 的相对位置，以及包格式版本。标记中的每个路径必须是相对路径，且解析后仍位于该预备分包目录内。

导入器扫描用户所选文件或文件夹时，优先识别此标记：

- 有效标记、原文 TXT 和有效 MP3 都存在时，建立一个新的普通待处理任务。
- 新任务使用原文作为输入、复制正片音频为“导入音频”，因此跳过 TTS。
- 任务不继承旧图片、封面、Short 或旧运行状态。开始任务后，现有流水线会调用图片 API 重新生成图片，并据此与导入的音频合成正片 MP4。
- 缺少标记、原文或有效音频时，不把该目录当作可恢复预备分包，而保持现有 TXT/MP3 扫描行为，并向用户报告可理解的错误。

Short 的文字和音频为留档内容，本次不自动恢复或重新生成 Short。

## 用户界面

进入预备分模式前的确认提示改为说明：不会保留正片或 Short MP4；会保留原文、音频、图片、封面和 Short 的非视频资料；该目录可在以后通过“导入文件 / 文件夹”重新导入，以调用图片 API 重做图片和正片合成。

## 安全与失败处理

预备分整理继续使用暂存目录和失败回滚。为了避免在中途失败时误删 MP4，先仅将允许保留的非 MP4 文件移入暂存区，原任务目录在全部保留文件成功暂存后才删除。

识别预备分包时严格校验标记版本、路径范围、原文扩展名和 MP3 可读性。导入失败不能创建半成品任务。

## 测试

- 预备分包的根目录和嵌套 `shorts` 目录不含 `.mp4`，但保留所需音频和文字资料。
- 预备分包写入有效标记，且标记不包含绝对路径。
- 有效预备分包会被导入逻辑转换为“原文 + 导入 MP3”任务输入。
- 无效标记、越界路径、缺失原文或无效 MP3 都不能被当作恢复包导入。

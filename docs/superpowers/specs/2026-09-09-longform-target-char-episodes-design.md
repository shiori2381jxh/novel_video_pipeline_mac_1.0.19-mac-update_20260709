# 长篇项目目标字数分集

## 目标

长篇连续制作的每集长度以项目级、可编辑的“目标字数”为主。默认目标为 22,000 字，默认最少字数为 18,000 字，最多字数保留为 88,000 字。目标、最少和最多均指洗稿并朗读净化后的旁白字数。

## 设置与兼容

- 在项目页“长篇连续制作”区域增加“目标字数”输入框，放在最少与最多字数之间。
- 新项目默认保存 `target_final_chars: 22000`、`min_final_chars: 18000`、`max_final_chars: 88000`；这三个值都可按项目修改。
- 全局默认设置同样提供可编辑的目标字数默认值。
- 旧项目和旧批次记录缺少 `target_final_chars` 时，读取时回填 22,000，保证不因升级失败；已创建批次继续使用其冻结的设置快照。
- 校验三个值均为正整数，并要求 `min <= target <= max`。

## 分章策略

规划器只在完整章节边界分集，不从章节中间截断：

1. 从当前章节开始累计估算的洗稿后字数。
2. 若累计不足最少字数，必须继续加入下一完整章。
3. 达到最少字数后，比较“当前停止”和“加入下一整章”距目标字数的绝对差，选择更接近目标的一侧。
4. 选定后立即结束本集，不再因为尚未达到最多字数而继续追加章节。
5. 单章本身超出最多字数，或为满足最少字数而加入的整章导致超过最多字数时，保留完整章节并给出超长警告。
6. 到书末仍不足最少字数时，保留最后一集并给出书末不足最少字数的警告。

## 数据流与展示

- 书库与 TXT 两条创建批次路径都将目标字数传入规划器。
- 批次设置快照、任务组确认对话框和项目加载/保存均携带目标字数。
- UI 提示明确说明“目标字数优先，最少/最多字数兜底；不拆章节”。

## 验证

- 覆盖新项目默认值、旧记录的目标回填和输入校验。
- 覆盖达到最少字数后选择离目标更近的整章边界。
- 覆盖不足最少字数时的强制补章、超上限整章保留、书末不足警告，以及批次快照保存目标值。
- 执行既有长篇项目测试和项目安全验证包。
